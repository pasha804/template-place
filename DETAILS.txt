1. PROJECT ARCHITECTURE OVERVIEW
================================================================================
Shaukat Techs Templates is a high-performance, full-stack digital web template 
and personalized dedication web page platform. It enables users to browse, 
customize, save, order, and publish Awwwards-quality interactive event pages 
(Weddings, Birthdays, Anniversaries, Proposals, Apologies, Congratulations).

Core Technology Stack:
- Framework: React 18 / Vite 5 / TanStack Start (SSR/SSG Hybrid Output)
- Router: TanStack Router (Strictly typed file-based routing)
- Data Fetching & Caching: TanStack Query (React Query v5)
- State Management: Zustand v4 (Template Editor Store & Auth Store)
- Database & Auth: Supabase (PostgreSQL with Row Level Security, RPCs, GoTrue Auth)
- Design System & Styling: TailwindCSS v3, Custom Vanilla CSS Modules, OKLCH Color Spaces
- Animation Libraries: Framer Motion v11, Canvas Confetti, Lucide Icons
- Server/Build Engine: Nitro Engine / Wrangler Target for Cloudflare & Vercel deployment

Architecture Diagram:
[ User / Browser ] 
       │
       ├──> [ TanStack Router (file-based: /templates, /editor, /checkout, /p/$slug) ]
       │          │
       │          ├──> [ Editor Engine (Zustand Store + FieldWidgets) ]
       │          │          │
       │          │          └──> [ LocalStorage Backup & Supabase Pages Table ]
       │          │
       │          └──> [ Public View Engine (/p/$slug) ]
       │                     │
       │                     └──> [ Dynamic Plugin Auto-Discovery (import.meta.glob) ]
       │                                │
       │                                └──> [ External Template Renderer (Zero-wrapper iframe-less DOM) ]
       │
       └──> [ Backend (Supabase PostgreSQL + RLS + Storage + Edge Functions) ]

3. ROUTING SYSTEM (TANSTACK ROUTER)
================================================================================
The application utilizes TanStack Router with strict TypeScript route typing 
and file-based routing located in `src/routes/`.

Key Routes Summary:
- `/` (`src/routes/index.tsx`): Main landing page with HeroSection, FeaturesShowcase, 
  CategoriesSection, StatsSection, TestimonialsSection, FAQSection, CTABanner.
- `/templates/index.tsx`: Catalog page listing all 16 external templates with 
  filters by category (Wedding, Birthday, Anniversary, Proposal, Sorry, Congratulations).
- `/editor/template/$templateId`: Live template editor. Accepts `pageId` query search param.
  Loads page config from Supabase or localStorage fallback.
- `/checkout/$pageId`: 3-step checkout page (Plan selection -> Payment method & screenshot upload -> Order confirmation & WhatsApp link).
- `/p/$slug`: Public published page viewer. Renders the external template engine 
  with zero outer application wrappers, giving the template full control of the viewport.
- `/auth/login`, `/auth/signup`, `/auth/forgot-password`, `/auth/reset-password`: 
  Authentication routes.
- `/dashboard/*`: User dashboard routes (`/dashboard/index.tsx`, `pages.tsx`, `orders.tsx`, `profile.tsx`, `settings.tsx`).
- `/admin/*`: Admin management panel for site administrators to review orders, 
  approve page publications, and manage users.

4. AUTHENTICATION SYSTEM (SUPABASE AUTH)
================================================================================
Authentication is managed via Supabase GoTrue Auth integrated through custom hooks 
and Zustand state (`src/hooks/use-auth.ts`, `src/store/auth.ts`).

Authentication Flow:
1. `signInWithPassword`: Validates credentials against Supabase.
   - If invalid: Catches error, displays toast notification ("Incorrect password or email", 
     "Account does not exist"), and halts execution. Never displays false "Welcome" message.
   - If valid: Establishes session, updates `useAuthStore`, and redirects to `/dashboard`.
2. OAuth Integration: Supports Google OAuth via `signInWithOAuth`.
3. Session Persistence: Listens to `supabase.auth.onAuthStateChange` to synchronize 
  session token and user roles.
4. Role Checks: Executes RPC `checkAdminRole` against `user_roles` table to grant 
  admin panel access to authorized users.

5. DATABASE SCHEMA & DATA MODEL (SUPABASE POSTGRES)
================================================================================
The database operates on PostgreSQL with Row Level Security (RLS) policies.

Primary Tables:
1. `pages`:
   - `id`: UUID (Primary Key, default `gen_random_uuid()`)
   - `user_id`: UUID (FK to `auth.users.id`)
   - `template_id`: String (References template plugin ID; nullable for custom external IDs)
   - `title`: Text
   - `slug`: Text (Unique index for `/p/$slug` routing)
   - `status`: Text (`'draft'`, `'pending_approval'`, `'published'`, `'archived'`)
   - `content`: JSONB (Holds full `TemplateConfig` object including `_template_id`)
   - `blocks`: JSONB (Legacy array)
   - `theme`: JSONB (Theme overrides)
   - `is_public`: Boolean
   - `expires_at`: Timestamp
   - `created_at` / `updated_at`: Timestamps

2. `orders`:
   - `id`: UUID (Primary Key)
   - `user_id`: UUID (FK to `auth.users.id`)
   - `page_id`: UUID (FK to `pages.id`)
   - `template_id`: Text
   - `template_name`: Text
   - `plan_key`: Text (`'basic'`, `'premium'`, `'deluxe'`)
   - `price_paisa`: BigInt (Amount in PKR paisa)
   - `payment_method`: Text (`'easypaisa'`, `'bank'`, `'paypal'`)
   - `payment_screenshot`: Text (Base64 or URL of payment receipt)
   - `status`: Text (`'pending'`, `'verified'`, `'rejected'`, `'completed'`)
   - `reference`: Text (Human-readable Order Ref: `ORD-XXXXXX`)
   - `whatsapp_sent`: Boolean

3. `page_views`:
   - `id`: UUID (Primary Key)
   - `page_id`: UUID (FK to `pages.id`)
   - `device`: Text (`'mobile'`, `'tablet'`, `'desktop'`)
   - `referrer`: Text
   - `created_at`: Timestamp

4. `user_roles`:
   - `user_id`: UUID (FK to `auth.users.id`)
   - `role`: Text (`'admin'`, `'moderator'`, `'user'`)

Foreign Key Violation & Local Fallback Strategy:
External templates use string IDs (e.g. `'wedding-eternal'`). If direct DB insertion 
fails due to FK constraints on remote `templates` table, the engine automatically:
1. Retries DB insertion with `template_id: null` while storing `_template_id` in `content`.
2. Creates a backup draft entry in `localStorage` under `page_${pageId}`.
This ensures 100% offline and local resilience for page creation, editing, and checkout.

6. TEMPLATE PLUGIN ENGINE
================================================================================
The platform features an extensible plugin architecture located in `src/engine/`.

Auto-Discovery Mechanism (`src/engine/registry.ts`):
Plugins are automatically discovered at compile time using Vite's `import.meta.glob`:
```ts
const modules = import.meta.glob<{ default: ExternalTemplatePlugin }>(
  "../external-templates/*/index.ts",
  { eager: true }
);
```
To register a new template, developers simply create a new directory inside 
`src/external-templates/<template-name>/` with an `index.ts` file exporting 
the `ExternalTemplatePlugin` interface. No central registry edits are needed.

Plugin Interface (`src/engine/types.ts`):
```ts
export interface ExternalTemplatePlugin {
  manifest: TemplateManifest;
  schema: SectionDef[];
  defaults: TemplateConfig;
  Renderer: React.ComponentType<{ config?: TemplateConfig; mode?: "edit" | "view" }>;
}
```

7. RENDERING PIPELINE & ISOLATION
================================================================================
Templates require total stylistic isolation so that global platform styles (e.g. 
dark marketplace navigation, administration styles) do not interfere with the 
template's unique typography, backgrounds, or keyframe animations.

Isolation Strategy:
1. Outer Container Scope: Each template wraps its output in a root container class 
   (e.g., `.we-root`, `.wp-root`, `.ct-root`, `.ag-root`).
2. Scoped Styling: CSS tokens, variables, and fonts are scoped inside inline `<style>` 
   blocks within the template `Renderer.tsx`.
3. Body Class Injection: When viewing a page at `/p/$slug`, `document.body` is assigned 
   the `.template-page` class to strip default margin/padding and background colors, 
   allowing the template engine full viewport dominance.

8. EDITOR SYSTEM & FORM CONFIGURATION
================================================================================
The editor is located at `src/routes/editor/template/$templateId.tsx`. It provides 
a clean, full-width configuration page designed for maximum data-entry focus.

Core Editor Components:
- `EditorTopBar.tsx`: Top bar displaying page title, unsaved status indicator, 
  Undo/Redo buttons, Manual Save button, and "Continue → Checkout" button.
- `EditorFormPanel.tsx`: Full-width form container rendering schema sections as 
  collapsible accordion cards (`mainSections` and `pageSection`).
- `FieldWidget.tsx`: Generic input control renderer mapping `FieldDef` definitions 
  to actual interactive input controls.

Supported Controls in `FieldWidget.tsx`:
- `text`: Single-line text input.
- `textarea`: Multi-line text area with adjustable rows.
- `color`: Hex color picker with visual color preview box.
- `boolean`: Smooth toggle switch.
- `number` / `range`: Sliders and numeric inputs.
- `select`: Dropdown selection widget.
- `date`: HTML5 date picker.
- `image` / `gif` / `audio` / `video`: Media file upload widget supporting local 
  FileReader Data URLs and direct URL input.
- `list-text`: Dynamic list of string items with add/delete actions.
- `list-image`: Responsive grid of image thumbnails with add/remove capability.
- `list-cards`: Dynamic card array editor supporting both string cards and structured 
  object cards (e.g. story milestones with `title`, `date`, `text`, `imageUrl`).

Autosave & State Synchronization:
- Auto-saves every 30 seconds if `isDirty` is true.
- Updates Zustand `useTemplateEditorStore` in real-time.
- Writes full payload to both Supabase `pages` table and `localStorage` backup (`page_${pageId}`).

9. SCHEMA & FIELD SYSTEM
================================================================================
Each template defines a formal schema array (`SectionDef[]`) in its `schema.ts` file.

Schema Structure:
```ts
export interface SectionDef {
  key: string;
  label: string;
  icon?: string;
  fields: FieldDef[];
}

export interface FieldDef {
  key: string;
  label: string;
  kind: "text" | "textarea" | "color" | "boolean" | "number" | "range" | 
        "select" | "date" | "image" | "gif" | "audio" | "video" | 
        "list-text" | "list-image" | "list-cards" | "pin" | "gradient" | "font";
  placeholder?: string;
  help?: string;
  options?: { label: string; value: string }[];
  min?: number;
  max?: number;
  step?: number;
  rows?: number;
}
```

This generic schema system ensures that any newly added field in a template's `schema.ts` 
automatically renders the corresponding UI input control in the editor without modifying 
the core editor source code.

16. STATE MANAGEMENT (ZUSTAND & TANSTACK QUERY)
================================================================================
The application employs a dual-tier state management strategy:

1. Client Interactive State (Zustand):
   - `useTemplateEditorStore` (`src/store/templateEditor.ts`): Tracks active `templateId`, 
     `pageId`, `config` object, `isDirty` state, `isSaving` state, `lastSaved` timestamp, 
     and manages an undo/redo history stack up to 30 snapshots.
   - `useAuthStore` (`src/store/auth.ts`): Stores current auth `user`, `session`, `isAdmin` flag.

2. Server Data & Cache (TanStack Query):
   - Handles asynchronous API calls to Supabase, query invalidation, background refetching, 
     and mutation caching for pages, views, and orders.

17. API & BACKEND INTEGRATION
================================================================================
The application connects directly to Supabase via `@supabase/supabase-js` client initialized 
in `src/integrations/supabase/client.ts`.

RPC Endpoints & Operations:
- `supabase.rpc("is_admin")`: Verifies if the authenticated user possesses admin privileges.
- `supabase.from("pages").insert(...)`: Inserts page drafts.
- `supabase.from("pages").update(...)`: Updates draft configs or publishes pages.
- `supabase.from("orders").insert(...)`: Places customer orders with payment receipts.
- `supabase.from("page_views").insert(...)`: Logs anonymous page view analytics.

================================================================================
18. SUPABASE STRUCTURE, RLS & TRIGGERS
================================================================================
Row Level Security (RLS) Policies:
- `pages`: Users can read/write their own pages (`auth.uid() = user_id`). Published pages 
  (`is_public = true` AND `status = 'published'`) are readable by anonymous users (`public`).
- `orders`: Users can insert orders and view their own orders (`auth.uid() = user_id`). 
  Admins can view and update all orders.
- `page_views`: Insertable by public/anonymous visitors for analytics tracking.

  JavaScript chunks (e.g. `_templateId-*.mjs`, `_slug-*.mjs`).
- Eager Asset Discovery: `import.meta.glob` eliminates bulky hardcoded import lists 
  while keeping bundle tree-shaking active.
- CSS Scope Scoping: Inline CSS styles scope template keyframe animations to prevent 
  global layout reflows during page rendering.
- Gzip Compression: Build bundles average 1.5 kB - 15 kB gzipped per route chunk.
